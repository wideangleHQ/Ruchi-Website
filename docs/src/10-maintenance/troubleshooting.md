# Troubleshooting

| Problem | Likely cause | Where to check | Safe solution |
|---|---|---|---|
| Products/collections show obviously fake data (Unsplash photos, round ₹ prices) | Shopify env vars missing/incorrect, or Shopify API unreachable — the mock-data fallback in `lib/shopify/index.ts` is active | `.env.local` values; network access to `*.myshopify.com` | Set correct `SHOPIFY_STORE_DOMAIN`/`SHOPIFY_STOREFRONT_ACCESS_TOKEN`; confirm with a direct GraphQL request before blaming the frontend. See [Error Handling](../04-frontend/error-handling.md) |
| A specific product/collection page 404s | Handle doesn't exist in Shopify, or isn't published to the sales channel this token can read | Shopify Admin → the product/collection's handle and channel visibility | Fix the handle/publish status in Shopify Admin — no frontend code change needed, routes are fully dynamic |
| Images missing/broken | `next/image` remote-pattern rejection (image host not in `next.config.ts` `images.remotePatterns`, which currently only allows `cdn.shopify.com`) | Browser console/network tab for the failing image URL's host | Add the host to `remotePatterns` in [next.config.ts](../../../next.config.ts), or move the image to Shopify/`public/` |
| Cart doesn't update after "Add to Cart" | Confirm which cart system the component you changed is wired to — a change to `cart-actions.ts` has no effect on the UI unless the component also switches away from `useCart()` | [cart-context.tsx](../../../src/components/cart/cart-context.tsx) vs [cart-actions.ts](../../../src/lib/shopify/cart-actions.ts) | See [Cart](../03-shopify/cart.md) / [Modifying Cart](../08-development/modifying-cart.md) |
| Checkout goes to a generic Shopify page with no items | Expected current behavior — the client cart's checkout link is a static URL | `cart-context.tsx`'s `checkoutUrl` | Requires the architectural fix in [Modifying Cart](../08-development/modifying-cart.md), not a quick patch |
| "Checkout URL missing" or similar Shopify API error | Only relevant if using the Shopify-backed cart path — check `ShopifyApiError` messages surfaced from `cart-actions.ts` | Server logs / the `{ error }` returned by the Server Action | Confirm the cart wasn't already converted to an order (`getOrCreateCart` handles this by creating a fresh cart, but only on the next call) |
| Environment variables missing | `.env.local` not created, or missing a key | Compare against [.env.example](../../../.env.example) | `cp .env.example .env.local` and fill in values; restart `npm run dev` after editing env files |
| Build failure | TypeScript error, or a Server/Client boundary violation (importing a `server-only` module into a `"use client"` file) | Build output; also try `npx tsc --noEmit` in isolation | Fix the reported type error; if it's a boundary violation, move the import or split the module |
| TypeScript errors | Usually a mismatch between a component's expected prop type and the Shopify types in `lib/shopify/types.ts` | `npx tsc --noEmit` output | Update the component's prop types or the Shopify type definitions to match reality — do not `as any` past them |
| Hydration errors | *General troubleshooting.* Most likely culprits in this codebase are components reading `localStorage`/`window` during initial render (`cart-context.tsx`'s `useState` initializer already guards with `typeof window !== "undefined"`, which is correct) | Browser console for the specific mismatch warning | Ensure any browser-only API access is guarded or moved into `useEffect` |
| Responsive problems | *General troubleshooting* — not a known/confirmed issue at time of writing | Visually test at the specific breakpoint reported | Adjust the relevant Tailwind responsive classes in the affected component |
| Vercel/deployment errors | *General troubleshooting* — deployment is not yet configured for this repo | Deployment platform's build logs, once one is connected | Confirm environment variables are set on the platform, and that the build command matches `next build` |

See also: [Development Workflow](../08-development/workflow.md), [Production Checklist](../09-deployment/production-checklist.md).
